# M7 结果报告：v1 加固与发布边界

日期：2026-08-30（证据主要生成于 2026-08-29）
状态：**macOS 核心验证和短 Soak 已通过；Beta 发布矩阵仍 Partial/Blocked**

## 本批完成

- 冻结常量：Save Format v1、World Schema 2、Migration Registry v1、Unity `6000.3.22f1`。
- 建立 Schema 1→2 迁移注册表，旧列表/对象字段缺失时补默认值，不改写旧文件。
- 增加 Frozen Save 文档、Canonical Hash 校验和 Golden Save/tamper 测试。
- 增加可复用对象池和引用计数纹理缓存；缺失或哈希错误资源回退占位，不删除棋子实体。
- 增加百分位性能采样工具，作为后续正式门槛的统一测量入口。
- 增加 1000 个可见棋子 PlayMode 性能场景与稳态分配采样；投影刷新复用活动集合、过期集合和位置解析集合，避免每次刷新创建临时集合。
- 增加棋子库虚拟化缩略图网格，定义列表不再用长按钮全量堆叠；实例列表独立显示，导入按钮改为“导入并重新绑定当前定义”，重复图片会复用现有内容。
- 将 Standalone 默认质量档从 Ultra 调整为 High，并把正式 Workbench 的桌面帧率策略固定为关闭 vSync、软件目标 60 FPS；性能采样入口额外支持解除限速以测量渲染承载能力。
- 增加 `scripts/unity-doctor.sh` 与 `scripts/unity-run-tests.sh`，固定 Unity `6000.3.22f1` 路径进行连接自检和 batchmode 验证。
- 增加 `scripts/macos-player-pacing.sh` 与可选的 `-sundoll-m7-perf-target-fps` 参数，区分解除限速的渲染承载测量和正式 60 FPS 限速 pacing 测量；macOS GUI Player 默认通过 LaunchServices `open -n -W` 启动，避免直接执行上下文触发 AppKit/LaunchServices 崩溃；同时扩展 Unity 启动前的孤儿 Licensing Client 清理，覆盖版本专用通道。
- 记录 Unity 连接诊断：当前没有 Unity MCP bridge/relay；近期反复“找不到连接”的主要证据是 Unity Licensing Client 通道协议不匹配、客户端崩溃/超时和网络证书/远程配置噪声。
- 将 Unity 启动策略集中到 `scripts/unity-common.sh`：测试、许可证自检、macOS 构建和交互式打开均固定版本专用许可证通道 `LicenseClient-sundoll-6000.3.22`，并对遗留通用客户端、临时锁和异常退出做安全保护。
- 新增 `scripts/unity-license-check.sh` 和 `scripts/unity-build-macos.sh`，分别提供独立许可证握手探针和带产物检查的 macOS Universal IL2CPP 构建入口；新增 `02-在Unity中编辑SundollWorld.command` 避免从 Hub 项目行启动导致通道漂移。
- 新增 `scripts/macos-player-smoke.sh`，构建后固定运行 Player 45 秒并检查启动日志，作为构建产物的可重复启动验收入口。
- 移除未使用的 `com.unity.visualscripting` 包，并在干净临时构建中确认 TypeDB 重复类型诊断清零。
- 修正 `M7ReleaseTests` 中的无用局部变量，避免新增 C# warning 干扰发布审计。
