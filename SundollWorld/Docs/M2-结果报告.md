## M2 功能覆盖

本轮已完成 Journal v2 命令 Payload 重放：新记录保存版本化命令 Envelope、Revision 前后值、可选 `WorldChangeSet` 和 Canonical Hash，不再同步写入完整世界 JSON；读取仍兼容旧 v1 `stateJson` 记录，并从 Revision Snapshot 之后按连续 sequence 重放。`M2SaveSession.Open/Reload` 可恢复 Snapshot 之后尚未进入新 Revision 的已接受命令，损坏尾部会停止在最后一条完整记录。

1. `HEAD.json`、不可变 Revision 目录和 Revision Manifest；HEAD 使用 generation、active revision 与 last-known-good revision。
2. UTF-8 原子写入、临时文件、`Flush(true)`、`File.Replace`/首次 `Move`，并在提交 HEAD 前后保留故障注入点。
3. Canonical SHA-256：对状态字段使用稳定顺序编码，地图单元格按坐标和内容 ID 排序，JSON 往返不会改变状态 Hash。
4. 分段 Journal：每条记录带 payload 校验和与状态 Hash；损坏尾部会被跳过，只恢复最近一条完整记录。
5. 自动保存策略：默认每 25 个正式事务或 180 秒触发；项目存储默认保留最近 10 个 Revision，并始终保护当前 HEAD/LKG。
6. 内容寻址 blob：用户资产与缩略图按 SHA-256 去重、读回时校验长度和 Hash，单 blob 上限为 64 MiB。
7. `.sundollpkg`：导出已验证的活动 Revision、HEAD 和内容 blob；导入使用 staging 目录并在完整性验证后原子移动。
8. 包安全检查：限制 Entry 数量 4096、解压总大小 256 MiB，拒绝路径穿越、绝对路径、反斜杠、重复 Entry 和未知顶层路径。

存档格式当前为 format/world schema `1` 的 pre-v1 草案，不承诺长期兼容，也没有读取历史网页项目格式的路径。
