# 项目格式 v0 草案

状态：M0 草案，pre-v1，可丢弃，不承诺长期兼容。

## 日常项目目录

```text
<name>.sundollproj/
  HEAD.json
  revisions/
    <save-revision-id>/
      revision-manifest.json
      project.json
      catalog.json
      maps/*.json
      scenarios/*.json
  assets/
    <sha256>.<ext>
  thumbnails/
    <sha256>.webp
  journal/
    <journal-stream-id>/
      <first-sequence>-<segment-id>.log
  staging/
```

便携包 `<name>.sundollpkg` 是只读 ZIP，默认只包含一个已验证 Revision、它引用的资产、Package Manifest 和可选缩略图；不包含 Journal、旧 Revision、本机布局、Undo、诊断、账号或认证信息。

## `HEAD.json`

```json
{
  "projectId": "stable-project-id",
  "activeSaveRevisionId": "save-revision-id",
  "activeJournalStreamId": "journal-stream-id",
  "generation": 7
}
```

HEAD 只在新 Revision 的全部逻辑文件、Manifest、Schema、引用、不变量和 Hash 验证成功后，通过同卷临时文件 + `replace` 最后提交。写入失败必须保留旧 HEAD。

## Revision Manifest

最低字段：

- `saveRevisionId`、`parentRevisionId`
- `formatVersion`、`worldSchemaVersion`
- `minReaderFormatVersion`、`minReaderWorldSchemaVersion`
- `snapshotWorldRevision`
- `snapshotJournalStreamId`、`snapshotOperationSequence`
- `canonicalStateHash`
- 逻辑文件表、大小和 SHA-256
- Content Manifest Hash、Ruleset ID/Hash、扩展依赖
- App/Build ID、UTC 时间和安全展示摘要

Manifest 不把自身列入自身 Hash。Canonical State Hash 排除时间戳、缩略图、本机偏好、Undo、诊断和显示摘要；集合按稳定 ID 排序，坐标和旋转使用量化值。

## 扩展数据

```json
{
  "typeId": "package-id:component-id",
  "version": 1,
  "data": {}
}
```

未知扩展保留原始 UTF-8 Payload 和 Hash，未安装扩展时仍可 round-trip。禁止使用 CLR 完整类型名、输入驱动的反射实例化或 `BinaryFormatter`。

## 恢复 Journal

一个成功事务写成一个完整 `AcceptedOperationBatch`，包含长度/Hash、Command ID、Journal Stream ID、World Revision、Operation Sequence 和版本化 Payload。恢复只接受完整且 Hash 正确的 Batch；损坏尾部可以丢弃，不可以应用半个事务。Snapshot 只重放同一 Stream 中连续的 `sequence > S`。
